# Guia do Atleta

Este guia é para quem nunca usou o GitHub. Você não precisa saber programar: basta um navegador. Ele mostra como **ler** as regras das competições cearenses e como **sugerir** uma mudança.

## 1. Ler o regulamento

1. Abra o [README](README.md#regulamento-em-vigor) e vá à seção **Regulamento em vigor**.
2. Escolha o formato:
   - **ler o texto** abre o regulamento direto no navegador;
   - **baixar o PDF** serve para guardar e imprimir.
3. O regulamento é dividido em capítulos numerados. Cada capítulo traz seus artigos (**Art. 1º**, **Art. 2º**...), e cada artigo pode ter parágrafos e itens (a., b....).

**Como achar um assunto:** use a busca do navegador, com `Ctrl + F` (no Mac, `Cmd + F`). No celular, abra o menu do navegador e escolha "Localizar na página". Digite uma palavra-chave, como *inscrição* ou *premiação*. Se o GitHub mostrar um botão de lista no canto superior direito do arquivo, ele abre o índice dos capítulos.

**E o que o regulamento não trata?** Valem as Regras de Orientação Pedestre (ROP), da CBO, que estão na mesma seção do [README](README.md#regulamento-em-vigor).

## 2. Escolher como sugerir uma mudança

| Caminho | Como funciona | Seus dados |
| :--- | :--- | :--- |
| **Pelo clube** | Você leva a sugestão ao diretor técnico do seu clube, que a encaminha à FECORI. | Não precisa de conta e nada fica público no GitHub. |
| **Pelo formulário** | Você preenche o formulário [Sugestão de regra](https://github.com/Jouderian/Regulamentos-de-Orientacao/issues/new?template=sugestao-regra.yml) no GitHub e acompanha a resposta lá mesmo. | Seu nome completo, número CBO e clube ficam **públicos**. |

As sugestões dos dois caminhos são avaliadas juntas pelo diretor técnico da FECORI e pelos diretores técnicos dos clubes. Se você prefere não se expor, use o caminho pelo clube.

## 3. Sugerir pelo formulário, passo a passo

1. **Crie a conta gratuita** em [github.com/signup](https://github.com/signup). Informe e-mail, senha e um nome de usuário, e confirme o e-mail com o código que o GitHub enviar. Quem já tem conta só precisa entrar.
2. **Abra o formulário** [Sugestão de regra](https://github.com/Jouderian/Regulamentos-de-Orientacao/issues/new?template=sugestao-regra.yml) com a conta aberta.
3. **Preencha os campos**, todos obrigatórios:

   | Campo | O que escrever |
   | :--- | :--- |
   | **Nome completo** | Seu nome completo. |
   | **Número CBO** | Seu número de cadastro na CBO. |
   | **Clube** | O clube ao qual você é filiado. |
   | **Artigo afetado** | O local exato da regra, com artigo, parágrafo e item. Para uma regra nova, diga onde ela deve entrar. |
   | **Redação atual** | O texto de hoje, copiado do regulamento em vigor. Para uma regra nova, escreva "Não há". |
   | **Redação proposta** | O texto como você quer que fique. Para tirar uma regra, escreva "Revogar". |
   | **Justificativa** | Qual problema a mudança resolve. Se puder, cite a regra da ROP ou o caso que a motivou. |
   | **Declarações** | Marque as duas caixas: ciência de que os dados são públicos e conferência da redação atual. |

4. **Envie** pelo botão verde no fim da página.
5. **Anote o número** da página que o GitHub criar (algo como `#12`): é com ele que você acompanha a sua sugestão.

**Modelo de preenchimento.** É só um molde, não uma sugestão real:

> - **Artigo afetado:** Art. X, Parágrafo Y
> - **Redação atual:** [cole aqui o texto do parágrafo, igual ao do regulamento]
> - **Redação proposta:** [escreva o parágrafo como você quer que fique]
> - **Justificativa:** [explique o problema que isso resolve e, se souber, cite a ROP ou um caso que aconteceu]

## 4. Acompanhar a sua sugestão

O formulário cria uma página pública com número, chamada de *issue*. Você a encontra na [lista de sugestões](https://github.com/Jouderian/Regulamentos-de-Orientacao/issues?q=label%3A%22sugest%C3%A3o+de+regra%22) ou pelo aviso que o GitHub costuma enviar ao seu e-mail quando alguém comenta. O rótulo na página mostra em que ponto ela está:

| Rótulo | Significa |
| :--- | :--- |
| *(sem rótulo)* | Recebida; a equipe confere a sua identificação e se a sugestão está clara. |
| `situação: em análise` | A equipe de regras está preparando o parecer. |
| `situação: parecer pronto` | O parecer está escrito e a sugestão espera entrar na pauta. |
| `situação: na pauta` | Espera a deliberação do diretor técnico da FECORI e dos clubes. |
| **Fechada** | Já foi deliberada. O comentário final conta o resultado. |

Quando a sugestão é deliberada, o resultado fica registrado nela:

- **Aprovada:** o comentário traz a redação final, e uma tarefa separada leva o texto ao regulamento.
- **Rejeitada:** o comentário traz a justificativa.
- **Adiada:** a sugestão continua aberta, com a data em que volta a ser tratada.

## 5. Dúvidas frequentes

**Meus dados ficam públicos?** Ficam: nome completo, número CBO, clube e o nome de usuário da sua conta, visíveis para qualquer pessoa. Se isso incomoda, use o caminho pelo clube.

**Posso mudar o regulamento direto no GitHub?** Não. O texto só muda depois da deliberação da FECORI com os clubes. O que você faz é sugerir.

**Posso sugerir uma mudança na ROP?** Não por aqui. O formulário vale só para o regulamento cearense, porque a ROP é alterada apenas pela CBO.

**Errei alguma coisa no formulário. E agora?** Escreva um comentário na própria página da sua sugestão explicando a correção.

**Tenho outra dúvida.** Fale com o diretor técnico do seu clube.

Voltar ao [README](README.md).
